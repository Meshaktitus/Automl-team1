# Dataset Profiling (Team 1)



The module takes a table (CSV or XLSX file, or a pandas DataFrame the caller has already loaded) and returns a structured JSON profile: dimensions, column types, missing values, distinct counts, duplicates, summary statistics, histograms, correlations, an optional class distribution for a selected target, and warnings. It returns a structured error instead of raising, and never modifies the source data.

## Quick start

```
pip install -r requirements.txt
pytest                         # unit and contract tests
python integration_check.py    # 12 scenarios: success, warning and failed paths
python run_all.py data         # tests + HR tables; needs the HR Excel files in data/ (not in the repository)
```

## Use from Python

```python
from profiling_service import run_profiling

request = {"schema_version": "1.0-draft", "request_id": "demo-001",
           "dataset_reference": {"dataset_id": "ds-001", "source_type": "file"},
           "options": {"target_column": "plan"}}           # target_column is optional
response = run_profiling(request, dataframe=df)             # or set dataset_reference.location to a CSV/XLSX path
# response["status"] is "success", "warning" or "failed"
```

## Data policy

No dataset files are committed. The HR Excel files come from the backend team and the Employee table contains personal data. `samples/demo_customers.csv` is synthetic. Identifier columns never report values, statistics or histograms; date columns report their minimum and maximum, so treat outputs for sensitive datasets as sensitive.

## Limitations

The whole table is held in memory; only CSV and XLSX are read; there is no enforced path boundary, file-size limit or timeout yet. See `PROFILING_KNOWN_ISSUES.md`.
